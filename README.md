# Presidential campaign promise tracker

A personal research corpus tracking what US presidential candidates promised, what happened to those
promises, and how the press and public understood them. Files are the source of truth; SQLite is a
rebuilt index; every quote is mechanically verified against an archived source document at build time.

## Layout

```
data/schema/        enums.yaml (controlled vocabularies), categories.yaml, issues.yaml (era-spanning), events.yaml (kind: war/economic/political),
                    indicator_links.yaml (position category -> indicator ids, drives the timeline)
data/indicators/    one YAML per yearly statistical series (generated by `./pres indicators`; values keyed by year, cite an archived dataset doc)
data/people/        one YAML per person (spans cycles)
data/cycles/<year>/ cycle.yaml, candidates/, positions/, followthrough/, reception/  (1932 and 1936 so far)
archive/docs/<id>/  meta.yaml + text.txt (+ raw.html, gitignored) — every citation resolves here
presidential/       the code: archive.py, models.py (validation), build.py (SQLite), embed.py, web/, sources/
build/              presidential.db, embeddings.npz (generated; gitignored)
```

## Commands

```bash
./pres build            # validate data/ + archive/ and compile build/presidential.db (fails on any unverifiable quote)
./pres check            # validate only
./pres serve            # web UI at http://127.0.0.1:8321  (or: uv run python -m presidential serve)
./pres export           # freeze the web UI into ./site as a static site (see Publishing)
./pres embed            # similarity embeddings (model2vec; TF-IDF fallback offline)
./pres indicators       # fetch/refresh statistical series (FRED, Treasury, NCES) into data/indicators/ (+ archived datasets); --force re-downloads
./pres fetch <slug>...  # archive documents from presidency.ucsb.edu by URL slug
./pres docs             # list archived documents
./pres grep "phrase"    # find exact wording in the archive before writing a quote
./pres verify <doc> "quote"
```

Other fetchers (Python API): `presidential.sources.loc` (Chronicling America newspapers, loc.gov API),
`presidential.sources.ia` (archive.org OCR text), `presidential.sources.web` (any page/PDF with explicit citation).

## Timeline

`/timeline` charts yearly indicators (unemployment, GDP, CPI, federal debt/deficit/outlays, consumer credit, high-school
graduation) with an event lane (wars, economic, political) and election years. Every follow-through **mechanism** is
placed on the indicators mapped from its position's categories in `data/schema/indicator_links.yaml` (a mechanism may
also list `indicators: [...]` explicitly — the 1933 Hundred Days statutes do, pointing at narrower series: bank
suspensions for Glass-Steagall, prices received by farmers for the AAA, manufacturing hours/earnings for NIRA codes,
nonfarm foreclosures for the HOLC, construction contracts for PWA, gold stock and wholesale prices for the gold embargo). The before/after table shows the indicator at the action year and +1/+2/+4
years — what happened next, not what the action caused. Datasets are archived like any other document (`kind: dataset`,
line structure preserved) so each series cites its source. Notes: FRED silently stalls requests with a custom
User-Agent, so `sources/data.py` uses httpx's default; consumer credit only exists from 1943, so "average citizen
debt" for the 1930s is not available from a primary statistical source.

## Publishing

Every route is a read-only GET, so the whole UI can be frozen and hosted as static files:

```bash
./pres build && ./pres embed && ./pres export --out site
```

~2,000 pages, ~43 MB. `--base /subfolder` rewrites the links for a site served below the root,
`--site-url https://…` writes `sitemap.xml`/`robots.txt`, `--note "…"` puts a banner on every page.
Preview it with `python3 -m http.server 8322 --directory site`.

What the server does and a static file cannot, `presidential/web/static/site.js` does in the browser:
the filter forms on `/positions`, `/documents` and `/reception` submit to the unfiltered page and the
script hides rows that do not match (each row carries its filter keys as `data-*` attributes), quote
highlighting reads `?hl=`, and the timeline renders every series and toggles panels client-side.
Two things degrade: FTS5 search *inside* the archived document texts (the published search covers
titles, authors, dates and position text — the full index stays in the local app), and timeline date
ranges other than the ones linked from position pages.

`.github/workflows/publish.yml` runs build → embed → export → GitHub Pages on every push to `main`
(enable Pages with source "GitHub Actions"). Set the repo variables `SITE_URL`, `SITE_BASE` (e.g.
`/presidential` for a project page, empty for a custom domain) and `SITE_DOMAIN` to taste. To publish
somewhere else instead, upload the folder: `rsync -av --delete site/ user@host:/var/www/promises/`
(export with `--base /promises` if it is not at the root).

Before making the archive public, check the reuse terms per source: Chronicling America and federal
statistics are public domain, Wikipedia extracts are CC BY-SA 4.0 (document pages say so), the American
Presidency Project transcribes public-domain documents but asserts rights over its compilation, and the
Internet Archive scans are only as free as the underlying issue. Each document page carries its citation
and a link to the original.

## The data model

- **position** — issue + solution + rationale, with `kind` (pledge_forward / defense_of_record),
  `commitment_strength` (specific_pledge / directional_stance / vague_gesture), `attribution`
  (candidate_direct / surrogate / party_platform / reported / imputed_uncorrected / opponent_characterization),
  `evidence_quality` A–D, `triggered_by` events, and dated **statements** each citing a `doc` and a `quote`.
  Statements accumulate, so drift is visible (see `1932-fdr-public-works-only-a-stopgap` → `supersedes`).
- **followthrough** — verdict (kept / partial / broken / reversed / superseded / blocked / abandoned /
  not_applicable), `contested` flag, mechanisms (statute, EO, veto…) with docs, sourced assessments,
  obstruction reasons, and `enacted_by_other` links for losers' ideas that later became law.
- **reception** — what a source (editorial, poll, opposition, historiography) understood the candidate to
  stand for, with `fidelity` (accurate / distorted / inverted / ignored / unaware) and `salience`.

Quotes may use ` ... ` to elide; each segment must appear in order in the archived text. Matching ignores
case, punctuation and whitespace, so OCR hyphenation does not break verification, but the words must match.

Positions that continue an earlier one carry `supersedes:` (e.g. the 1936 balanced-budget pledge supersedes 1932's).

## Adding a cycle

1. Fetch the sources (`./pres fetch`, or the loc/ia/web fetchers) so every citation has a `doc`.
2. Write `data/cycles/<year>/cycle.yaml`, candidate records, then positions from the sources (use
   `./pres grep` to copy exact wording). Add new issues to `issues.yaml` rather than overloading old ones.
3. `./pres build` until it passes; then followthrough and reception.
4. `./pres embed` to refresh similarity; `./pres indicators` if the cycle needs series not yet in `data/indicators/`.
